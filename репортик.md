# Дневник выполнения лабораторной работы №2


## 1. Подготовка окружения

Я использовала docker-compose.yml, в котором описаны два сервиса: 
PostgreSQL (bigdata_spark_postgres) и ClickHouse (bigdata_spark_clickhouse). 
Базы данных запускаются в изолированных контейнерах и связаны общей сетью.

PostgreSQL настроен на порт 5432, ClickHouse - на порты 8123 и 9000. 
Для PostgreSQL заданы логин postgres, пароль 12345, база postgres.
Для ClickHouse - логин default, пароль clickhouse123.


## 2. Загрузка данных

При запуске контейнера PostgreSQL автоматически выполняются скрипты:
- DDL.sql (создание таблицы mock_data в схеме public)
- mock_data.sql (копирование данных из 10 CSV-файлов)
- DML.sql (заполнение аналитических таблиц)
- analysis.sql (проверочные запросы)

CSV-файлы лежат в папке "исходные данные" и монтируются в контейнер.

После загрузки я выполнила проверочные запросы из analysis.sql:
- SELECT COUNT(*) FROM public.mock_data → 10000 строк
- SELECT COUNT(DISTINCT sale_customer_id) → 1000 уникальных покупателей
- SELECT COUNT(DISTINCT sale_product_id) → 1000 уникальных товаров
- SELECT MIN(id), MAX(id) → id от 1 до 1000

Все данные загружены корректно.


## 3. Модель "Звезда" в PostgreSQL

Скрипт DDL.sql создаёт схему analytics и 6 таблиц:

Измерения (dim):
- dim_customer (customer_id, email, имя, возраст, страна, данные о питомце)
- dim_seller (seller_id, email, имя, страна)
- dim_product (product_id, название, бренд, цена, категория, вес, цвет, размер, материал)
- dim_store (store_id, название, локация, город, штат, страна, телефон, email)
- dim_supplier (supplier_id, название, контакт, email, телефон, адрес)

Факты:
- fact_sales (sale_id, внешние ключи на все измерения, дата, количество, сумма)

Скрипт DML.sql заполняет эти таблицы данными из public.mock_data:
- INSERT в dim_customer - через SELECT DISTINCT, ON CONFLICT по email
- INSERT в dim_seller - через SELECT DISTINCT, ON CONFLICT по email
- INSERT в dim_product - через SELECT DISTINCT
- INSERT в dim_store - через SELECT DISTINCT, ON CONFLICT по store_name
- INSERT в dim_supplier - через SELECT DISTINCT, ON CONFLICT по supplier_name
- INSERT в fact_sales - через JOIN с измерениями по бизнес-ключам

Схема базы данных изображена на отдельной картинке.


## 4. Проверка данных через Spark

Я написала тестовый скрипт test_spark.py, который:
- подключается к PostgreSQL через JDBC
- читает таблицу public.mock_data
- выводит количество строк (10000) и первые 5 записей
- считает выручку по категориям товаров через groupBy("product_category")

Скрипт работает, Spark успешно соединяется с PostgreSQL.


## 5. Отчёты в ClickHouse

Скрипт etl_to_clickhouse.py формирует следующие витрины:

**Продукты:**
- top_products - топ-10 товаров по выручке
- revenue_by_category - выручка по категориям
- product_ratings - топ-10 продуктов по рейтингу

**Клиенты:**
- top_customers - топ-10 клиентов по тратам + средний чек
- customers_by_country - количество клиентов по странам

**Время:**
- monthly_trends - выручка, количество заказов, средний чек по месяцам

**Магазины:**
- top_stores - топ-5 магазинов по выручке + средний чек

**Поставщики:**
- top_suppliers - топ-5 поставщиков по выручке + средняя цена товара

**Качество продукции:**
- top_rated_products, lowest_rated_products - продукты с высшим и низшим рейтингом
- most_reviewed_products - продукты с наибольшим количеством отзывов
- rating_correlation - корреляция между рейтингом и объёмом продаж (значение: 0.0348)
